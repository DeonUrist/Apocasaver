# Apocasaver 2.0.4 performance verification

Validated 13 October 2026 against the installed Unity 2020.3.49 / BepInEx 5 runtime. This update starts from
[PR #1](https://github.com/DeonUrist/Apocasaver/pull/1), merged with its original contributor commit preserved.

The update addresses terrain-template lookup, repeated history copies, processing outside native pool batch ranges,
cleanup searches before eligibility, cleanup tracking when disabled, and repeated per-pose disk writes.

| Check | Result |
| --- | --- |
| Release build against installed game assemblies | 0 warnings, 0 errors; deployment disabled during validation |
| Managed transaction/compatibility/filesystem suite | 100 checks passed |
| Native pool/save/load/cache/companion API binding checks | Passed |
| Isolated native Unity fixtures without companions | 78 passing report lines |
| Isolated native fixtures with Apocapatrol 2.13.0 and Apocapocket 2.0.10 | 93 passing report lines |
| Whitespace/diff validation | Passed |

The native performance regressions establish that:

- Real MoveItems hooks capture and restore only `[startNum,endNum)`; the other roots keep their state and position.
  Empty batches do no history work. ClampCount captures only the removed tail before native destruction.
- Templates come from the pool prototype. Same-name prefabs keep independent defaults, destroyed Unity template
  wrappers are looked up again, runtime-child misses are remembered, and scene/session reset clears cached templates.
- 200 native restores with 10,000 synthetic history records create one snapshot. The final fixture runs measured
  17.767 ms without companions and 11.694 ms with companions for the complete loop, including FSM load events,
  reflection in the test caller and instrumentation. These are constructed-fixture timings, not streamed gameplay
  frame times or a controlled speedup ratio against the prior release.
- Capturing newer history invalidates the snapshot. A Load callback that writes into the scratch file makes it dirty,
  forcing reconstruction before the next site; the writes do not enter the source ledger. Scratch files are removed
  from ES3's registered caches after each event batch, preventing accidental automatic disk storage.
- CleanSaves disabled performs no periodic registry scan. Enabling it starts new distance timing. Ineligible roots
  do not build a reference index, while multiple eligible roots share one index. Uninitialized external owners still
  protect their references, and final validation detects an external reference added after planning.
- Three delayed hand poses produce one disk commit, retain unrelated records, and remain pending after a real disk
  lock until a successful retry. During a save, poses enter the transaction cache without intermediate disk writes;
  public reads see the current metadata, and rollback restores the prior disk save.

The prior native coverage also passes: occupied/fresh slots, source-world isolation, terrain history, stable hinge
keys, file-only and delayed mod state, confirmation diagnostics, actual disk-lock rollback and patrol cleanup.

Reproduce with:

```powershell
dotnet build Apocasaver.csproj -c Release -p:SkipDeploy=true
dotnet run --project verification/Verification.csproj -c Release
powershell.exe -NoProfile -ExecutionPolicy Bypass -File verification/CheckBindings.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File verification/RunNative.ps1 -NoMods
powershell.exe -NoProfile -ExecutionPolicy Bypass -File verification/RunNative.ps1
git diff --check
```

Local native evidence is in `verification/results/vanilla-20261013-092053/report.txt` and
`verification/results/mods-20261013-092104/report.txt`. Those runtime output directories are ignored by Git.
The fixture runners use isolated save paths and separate plugin/config directories; they do not install their test
plugins into the player's game. A driving-route replay and long-session frame/GC capture remain useful follow-ups.
