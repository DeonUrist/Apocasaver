Fixes 2.0.0's false startup **"Save recovery/bindings failed: Save participant is still loading: …apocapatrol"** error.

The game can destroy a plugin's original Unity component while its managed wrapper, static configuration and persistent runner remain valid. Apocasaver mistook Unity's destroyed-component null result for an unconstructed plugin and permanently blocked saving/loading.

- Resolve loaded companion integrations using managed reference identity, which remains valid after Unity destroys their components.
- Retry genuinely pending plugin initialization without treating it as a permanent recovery failure.
- Distinguish incompatible integration bindings from actual backup-recovery failures in logs and warnings.
- Add native regressions that destroy the Apocapatrol/Apocapocket components before initialization and simulate a pending instance.

**Install:** exit the game and replace `BepInEx/plugins/Apocasaver.dll` from the ZIP, then restart. Existing saves and settings require no changes. All 2.0.0 save rebuilding, history preservation and optional CleanSaves features remain included; CleanSaves is still off by default.

**Validation:** clean Release build; 91 automated checks; 27 native Unity fixture checks without companions and 39 with Apocapatrol 2.7.0 / Apocapocket 2.0.7. The companion run reproduces the reported destroyed-component condition and verifies successful saves, rollback, pocket mapping and patrol cleanup afterward. Full interactive and long-session validation remains pending.
