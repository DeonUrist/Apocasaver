# Apocasaver 2.0.1 startup regression verification

10 October 2026. Fixes the reported 2.0.0 startup false positive.

The live log showed Apocapatrol had already loaded before Apocasaver, then `SaveParticipants.Resolve` threw
`Save participant is still loading: com.denis.apocalypter.apocapatrol`. The original check used Unity's overloaded
`plugin.Instance == null`: a destroyed native plugin component evaluates as null even though its managed wrapper and
persistent mod runner remain valid. The game destroys those original plugin components on scene changes.

The corrected adapter checks CLR reference identity and uses the surviving wrapper's assembly. Truly unconstructed
instances defer initialization and retry instead of setting a permanent recovery error. Integration incompatibility and
backup-recovery failures now have distinct diagnostics.

Validation:

- Release build: zero warnings/errors.
- 91 managed filesystem/policy/compatibility checks.
- 27 native Unity no-companion checks: `verification/results/vanilla-20261010-220000/report.txt`.
- 39 native Unity companion checks: `verification/results/mods-20261010-215751/report.txt`.
- Installed ES3, pocket and patrol bindings verified.

The companion regression temporarily sets a Chainloader plugin instance to a real CLR null, verifies that initialization
defers without latching recovery failure, then restores the instance. It destroys both native companion plugin components
and verifies they evaluate as Unity null while retaining their managed wrappers. The actual production coordinator then
initializes and passes the save/history/rollback/pocket-mapping/patrol-cleanup fixtures in that state.

All save paths remain isolated from player saves. This targeted native reproduction closes the startup lifecycle gap in
the original fixtures. Full interactive and long-session validation remains pending.
